About This Manual

Documentation conventions, status labels, design references, and specification ownership.

Raz Gen2 Manual·AboutManual conventions

Purpose

The Raz Manual records the language surface, expected compiler responsibilities, standard-library APIs, and platform/toolchain behavior. The intent is to make feature decisions explicit before expanding the implementation.

Status labels

Status Meaning
Implemented Behavior is visible in the current source or test workflow.
Partial Some behavior exists, but the language or implementation contract has limitations.
Needs decision A design choice or public rule has not been settled.
Inconsistent The sources disagree or an implementation path appears unreachable.
Design reference An idea or name is inspired by another language; behavior is not presumed equivalent.

Documentation rules

  • Public manual pages are authored as static HTML and share a common stylesheet and navigation system.
  • Each feature should have a concise registry entry or index link and a dedicated page when detailed syntax or semantics matter.
  • Examples should reflect the actual implementation and avoid implying behavior that has not been specified.
  • Design references must state whether they are syntax, terminology, or conceptual inspiration.
  • The implementation snapshot and approved language contract must remain distinguishable.

Design references

The PHP Manual is a reference for documentation organization and concise feature pages. It is not a source of Raz semantics. Individual language pages cite conceptual references where relevant.
